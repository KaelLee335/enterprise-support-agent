# 架构说明

## 组件

- **Dify Chatflow**：统一编排用户输入、订单意图与知识问答。工作流 DSL 在 `../dify/support-agent.yml`。
- **Dify 知识库**：10 份 `../data/knowledge/` 下的模拟政策。导入 DSL 不会自动把这些文件或嵌入索引复制到另一实例。
- **订单只读 Code 节点**：从 DSL 内嵌的虚构订单快照查询状态；外部可审阅订单源 `../data/orders.json`。该路径不执行退款、取消或修改。
- **评估脚本**：`../scripts/run_eval.py` 调用 Dify Chatflow API，记录服务真实返回的数据；`../scripts/report.py` 汇总已保存运行。

## 请求流程

```text
用户输入 → 确定性订单/安全路由
                    ├─ 订单查询 → 只读演示订单 Code → 回复
                    └─ 售后问答 → 问法扩展 → Dify 知识检索 → 来源标注
                                                     ├─ 证据不足 → 安全说明
                                                     └─ LLM → 政策与引用守卫 → 回复
```

## 安全与观测边界

所有政策和订单为演示资料。无真实用户身份验证、写订单工具或人工工单系统。模型答复或引用标签不能证明检索命中、工具执行或真实转接。评估脚本只在 API 明确返回时记录 `retriever_resources`；路由、工具调用和动作日志缺失时保持 `null`。Latency 为客户端请求耗时，不能替代 Dify 内部节点耗时。
